## 2. トライアルで使えそうな考え方

### 予測

- 鉛直は `z = z0 + vz·t − ½gt²`、水平は等速で最小二乗。床 z = 0 との交点を解く。
  外部ライブラリなしで書ける大きさで、既知の放物線を入れて解析解と一致するかで確かめられる。
- 残差を予測の信頼度として返す。誤検出（人・手・背景）は残差で落とす。
- サンプル数を変えたときに誤差がどう縮むかを見られるようにしておくと、「何点要るか」の議論が数字でできる。

### 1投擲1レコードの記録形式

固定側の記録・再生・評価・シミュレータで同じ単位を扱うため、1投擲を1件の記録にした。旧形式のフィールド:

| フィールド | 中身 |
|---|---|
| `schema_version` | 形式の版 |
| `record_id` | 識別子 |
| `source` | `live` / `recorded` / `simulated` |
| `config` | 予測に使ったパラメータ |
| `samples` | 観測サンプルの列 |
| `predictions` | 予測結果の列（成功と失敗を `kind` で区別） |
| `extra` | 後から足す情報の置き場 |

### 入力元を差し替えられるようにする

実機（live）・記録（recorded）・合成（simulated）を同じ形で下流へ渡すと、
**一度記録した投擲を開発PCで何度でも再生できる**。実機の前に合成データで通しておける。

### シミュレータの出力に「信用できる範囲」を書く

掃引結果には、(1) モデルに入れていない要因の一覧、(2) 各パラメータの出所（測った値か仮の値か）、
(3) 較正の段階（机上の値だけか、実測で合わせたか）を必ず含めた。図だけ見て「成り立つ」と思い込まないため。
軸は「必要な横移動量 × 使える時間」で、各格子点を間に合う／間に合わないで塗る。

### 移動体の制御

- 逆運動学（輪 i の取付角を θi、中心から輪までを R として）:

  ```
  輪 i の周速 = −sin(θi)·vx + cos(θi)·vy + R·ω
  ```

  3 × 3 の行列なので、逆行列を取れば輪の速度から機体の速度（オドメトリ）も出る。
  輪の指令が上限を超えたら、3輪を同じ比率で縮める（向きを保つ）。
- PCNT のカウンタは 16 ビットで、すぐ一周する。前回値との差を取り、一周を考慮して積算する。
- PWM 上限は `min(1.0, 12.0 / 測ったバッテリ電圧)`。満充電 12.6V で約 0.952。
- ホスト上で PID を試すために、モータと輪の簡単なモデル（一次遅れ程度）を用意した。実機の前に、発散や飽和の扱いを確かめられる。
- 保護は「監視役」1つにまとめ、ロック・低電圧・PWM 上限・指令途絶のどれかが立ったら出力を止める形にした。

### コントローラ入力の割り当て（DualSense）

| 操作 | 割り当て |
|---|---|
| 左スティック | 並進 (vx, vy) |
| 右スティック X | 回転 ω |
| L1 / L2 など | デッドマン。押している間だけ出力を許す |
| 十字キー | 輪を1つ選んで単独で回す（台上の確認用） |
| 速度の上限 | 最初は 30% 程度 |
| スティック中立付近 | 不感帯と指数カーブを入れる（値は試して決める） |
| 振動 | モータロックを検出したら振動させる（任意） |

### Pi の診断コマンド

OS・Python・メモリ・SDK・デバイス・USB 速度・ストリームの開閉・給電・ディスクの9項目を1コマンドで返す `doctor` を作った。
環境を作り直したときに、どこまで動いているかが一目で分かる。中身は [dev-environment.md](./dev-environment.md#realsense-の確認コマンドpi-上) の確認コマンドとほぼ同じ。

### 機構

寸法を1か所のパラメータに集め、そこから形状を生成する作り方（build123d）は、採寸値を後から入れ替えられる点で便利だった。
トライアルでは、まず手で描いて刷り、合わない所を見つけてからパラメータ化するほうが早い。
