# 何を作るか

## 1. 目的

人が投げたゴミの**落下地点を空中で予測**し、床を走るゴミ箱が**落下時刻までにそこへ移動して受け止める**。
倉田捻氏の「Smart Trashbox」（文化庁メディア芸術祭受賞）への tribute で、個人の趣味プロジェクトである。

## 2. システム構成

```
Intel RealSense D435           ← 固定側: 飛んでいるゴミの3D位置を時系列で取る
        |
Raspberry Pi 4 Model B          ← 固定側: 放物線を当てはめ、落下地点と落下時刻を予測する
        |
        |  目標座標と到達時刻だけを送る（画像・Depth は送らない）
        v
      ESP32                     ← 移動体: 3輪の速度制御、自己位置の推定、安全停止
        |
  3輪オムニ移動体＋市販ゴミ箱
```

- 「知能（固定側）」と「身体（移動体）」を分け、**目標座標データだけ**で繋ぐ。元作品と同じ骨格であり、変えない。
- カメラは固定する。移動体にカメラは載せない。
- 固定側から移動体への通信方式は決まっていない（Wi-Fi UDP / シリアル / 固定側に ESP32 を置いて中継、などが候補）。
  Raspberry Pi から ESP-NOW を直接使えることは前提にしない。

## 3. 難しいところ: 時間予算

成否はほぼこの一点で決まる。

```
総飛行時間 0.6〜1.2s − システム側の遅れ 0.2〜0.3s = 移動体が使える時間 0.3〜1.0s
```

| 区間 | 想定 |
|---|---|
| 手を離してから検出が始まるまで | 0.05〜0.10s |
| 検出開始から予測が確定するまで | 0.10〜0.15s |
| 予測確定から移動体が動き出すまで（送受信を含む） | 0.05s |

この時間で、横方向の狙いのずれ（想定 0.3〜0.8m）を詰める。

- **数値はすべて想定であり、測っていない。** とくに「手を離してから検出が始まるまで」は根拠が無い。
- だから移動体の性能は**最高速度ではなく短時間の移動量**で見る。
  「静止状態から 0.4s / 0.6s / 0.9s で何 m 動けるか」を基本の物差しにする。
- 投げる位置と方向を固定して、必要な横移動を小さくするのは逃げではなく設計の一部として認める。

## 4. 成功条件

**キャッチ成功率**だけを最終の判定にする。

- 決めた投げ方で N 回投げ、キャッチできた割合。
- キャッチ＝**ゴミが開口に入り、跳ね出さずに留まる**こと。「入った」と「キャッチできた」は別。
  空き缶やペットボトルは硬い底で跳ねる。
- 目標の成功率も N も決めていない。予測と走行の実力を見てから決める。
- 速度・加速・遅延・位置精度などは途中の目安であって、全部満たしても成功とは限らない。

## 5. 予測の考え方

- 鉛直: `z(t) = z0 + vz·t − ½·g·t²`。水平 x, y は等速とする。空気抵抗は最初は無視する。
- 3点以上のサンプルに最小二乗で当てはめ、床（z = 0）との交点を落下地点・落下時刻とする。
  g を既知とすれば理屈では2点で解けるが、3点以上取るのはノイズに強くするためと、
  **当てはめの残差を予測の信頼度や誤検出の棄却に使う**ため。
- 位置精度の目安は「開口の半径 − ゴミの大きさの半分」。ゴミを点として扱わない。
  （例: 開口 φ200 に φ65 の空き缶なら ±67.5mm）

## 6. 座標系と校正

- 床を基準にした座標系を1つだけ使う（Z は床から鉛直上向き、単位は mm と ms）。原点と X/Y の向きは決めていない。
- 床平面はカメラの Depth から平面を当てはめて求める（D435 は IMU を持たない）。
- 設置のたびに次の校正が要る: 床平面の推定 → 原点と軸の決定 → 移動体の自己位置の原点合わせ →
  **既知の位置に物を置いて座標が合うか確かめる**。
- 座標が数 cm ずれていると必ず外すが、症状は「予測が悪い」ようにしか見えない。
  最後の確認手順を先に用意しておくと、ずれと予測誤差を切り分けられる。

## 7. 移動体に要る安全機能

演出ではなく、無いと危ないもの。

| 機能 | 内容 |
|---|---|
| モータロック保護 | 出力を出しているのにエンコーダが回らない状態が続いたら、そのモータを止める |
| 低電圧保護 | LiPo の電圧が下がったら警告し、さらに下がったらモータを止める |
| PWM 上限 | 満充電 12.6V のとき 12V モータに掛かる電圧を抑えられるようにする |
| 指令ウォッチドッグ | 最後に有効な指令から一定時間たったら止める。コントローラでも固定側からの通信でも同じ判定を使う |
| 動作領域の制限 | 決めた範囲の外の目標座標は捨てるか範囲内に丸める |
| 物理的な非常停止 | 未決。無線に頼る停止（デッドマンや接続断での停止）はこの代わりにならない |

## 8. やること・やらないこと

**やる**

- 屋内の平らな床（フローリングなど）
- 人が 2〜3m 先から山なりに投げる

**やらない**

- 段差越え、厚いカーペット
- 金属の切削加工が要る設計（手元にあるのは3Dプリンタだけ）
- ゴミの種類の判別（分別）
- 移動体へのカメラ搭載
- LED・音・キャラクター性などの演出（時間予算の役に立たないので後回し）

## 9. 決まっていない主なこと

- 投げ方（投げる位置・方向・距離）。成功条件を数字にするために要る
- 対象にするゴミの種類・大きさ・重さ
- 座標系の原点・軸と、校正の手順
- 目標地点で止まって待つか、通過しながら受けるか（止まるなら減速の分、要る加速性能がおよそ倍になる）
- Raspberry Pi 4 で必要な処理速度が出るか
- 固定側から移動体への通信方式
- 物理的な非常停止の手段
