# 移動体の回路

図は [circuit/schematic-draft.html](./circuit/schematic-draft.html)（たたき台・未完成）。
この文書はその数値と理由のテキスト版である。部品の型番は [hardware.md](./hardware.md) を見る。

**対象**: 3輪ぶんのモータとエンコーダ、ドライバ、電源、バッテリ電圧の監視。
固定側（Raspberry Pi・RealSense）の配線は含まない。

## 1. 電源の流れ

```
LiPo 3S（11.1V 公称 / 12.6V 満充電）
  │ XT60
 F1 10A ヒューズ           ← バッテリのすぐ後ろ
  │
 (SW1 メイン電源スイッチ)   ← 未決。図では破線
  │
 (TB1 電源分岐端子)         ← 未決。図では破線
  │  ＝ VM（12V バス。1本だけ）
  ├── U1 AE-TB67H450 ── M0
  ├── U2 AE-TB67H450 ── M1
  ├── U3 AE-TB67H450 ── M2
  ├── C1 / C2 1000µF
  ├── R1 100kΩ（電圧監視の分圧の上側）
  └── U4 BP5293-50 ── 5V ── JP1 ── ESP32 DevKit の VIN
                                     └ ESP32 の 3V3 ── エンコーダ VCC ×3、VREF ×3
```

- モータは LiPo からドライバへ直接つなぐ（間に降圧を挟まない）。
- BP5293-50 の出力は最大 1A。ESP32 の Bluetooth Classic 送信時のピーク（約130mA）、ボード（約20mA）、
  エンコーダ3個（約45mA）を足しても約300mA で、余裕がある。DevKit 上の 3.3V レギュレータが
  (5 − 3.3) × 0.3 ≒ 0.5W を熱にするので DevKit は温かくなるが、故障ではない。

### JP1（5V の切り離し）

| 場面 | JP1 | 5V をどこから取るか |
|---|---|---|
| USB をつないで書き込み・ログ確認 | **外す** | USB だけ |
| 走らせる（USB なし） | **挿す** | BP5293-50 だけ |

- USB の 5V と BP5293-50 の 5V が並列になると、片方からもう片方へ電流が逆流する（PC の USB ポートか、降圧コンバータの出力へ）。
- DevKit の 5V ピンが USB とダイオードでつながっているかは基板の版で違う。ジャンパにしておけば調べなくて済む。
- **切るのは 5V の1本だけ。GND はつないだままにする。**
- モータの 12V は別系統なので、JP1 を外していても USB 給電のままモータは回せる。

## 2. ネット

### 12V（動力）

| ネット | つなぐところ | 線 |
|---|---|---|
| `BAT+` | LiPo XT60(+) → F1 | 14AWG |
| `VM` | F1 の出力 → (SW1) → (TB1) → U1〜U3 の VM、U4 の入力、C1/C2 の (+)、R1 の上端 | 14AWG |
| `PGND` | LiPo XT60(−) → 星形接地点 `GND-STAR` | 14AWG |
| `OUT0+/−` | U1 の OUT1 / OUT2 → M0 の赤 / 白 | 動力線 |
| `OUT1+/−` | U2 の OUT1 / OUT2 → M1 の赤 / 白 | 動力線 |
| `OUT2+/−` | U3 の OUT1 / OUT2 → M2 の赤 / 白 | 動力線 |

OUT1→赤 / OUT2→白 は仮の基準。赤と白を入れ替えると回転方向が逆になる。どちらを正転とするかはモータ単体の確認（E-2）で決める。

### 低電圧

| ネット | つなぐところ |
|---|---|
| `+5V` | U4 の出力 → JP1 → ESP32 の `VIN` |
| `+3V3` | ESP32 の `3V3` → エンコーダ VCC（青）×3、U1〜U3 の VREF、可変抵抗 VR1 の上端 |
| `SGND` | ESP32 の `GND` → エンコーダ GND（黒）×3、VR1 の下端、C6 |

**エンコーダは 3.3V で動かす。** 5V をエンコーダへ配らない。5V の信号を ESP32 の GPIO へ直接入れない。
3.3V でカウント抜けやノイズが出たときだけ、5V 給電＋レベルシフタを考える。

### 電圧監視と机上確認用のつまみ

| ネット | つなぐところ |
|---|---|
| `VBAT_SENSE` | R1(100k) の下端 ＝ R2(27k) の上端 ＝ C6(0.1µF) → ESP32 GPIO32 |
| — | R1 の上端 → `VM`、R2 の下端 → `SGND`、C6 の下端 → `SGND` |
| `BENCH_POT` | VR1 のワイパ → ESP32 GPIO33 |

- 分圧比 27 / (100 + 27) ≒ 0.2126。12.6V → 約 2.68V、11.1V → 約 2.36V、9.0V → 約 1.91V。満充電でも 3.3V を超えない。
- **R1 の上端はヒューズとスイッチより後ろの `VM` につなぐ。** ドライバが実際に受けている電圧（加速時の降下を含む）を見たいのと、
  電源を切っているあいだ分圧が電池を減らし続けない（約 99µA）ようにするため。
- ESP32 の ADC は非線形で個体差がある。計算値を信じず、テスターで測ったバッテリ電圧と突き合わせて係数を決める。
- 分圧の合成抵抗は約 21kΩ と高いので、ADC の読みが暴れることがある。C6 で緩和し、足りなければ平均を取る。
- VR1 は机上確認用の仮設部品で、常設しない。

## 3. ドライバの8端子（U1〜U3 共通）

| # | 端子 | つなぐところ | メモ |
|---|---|---|---|
| 1 | GND | `PGND` → `GND-STAR` | 動力と論理で共通の GND。IN1/IN2 の基準もここ |
| 2 | IN2 | ESP32 GPIO 23 / 25 / 26 | 後進のとき PWM |
| 3 | IN1 | ESP32 GPIO 19 / 21 / 22 | 前進のとき PWM |
| 4 | VREF | `+3V3` ＋ 0.1µF → GND | 定電流制御を切るための印加（1〜5V、絶対最大 5.5V） |
| 5 | VM | `VM` ＋ 0.1µF → GND | 動作範囲 4.5〜44V |
| 6 | OUT1 | モータの赤 | 出力。GND ではない |
| 7 | RS | **GND へ直結**（抵抗を入れない） | 定電流制御を無効にする（データシート p.10） |
| 8 | OUT2 | モータの白 | 出力。逆転中は 12V が出る |

### IN1 / IN2 の動かし方（「案B」）

| 指令 | IN1 | IN2 | 動作 |
|---|---|---|---|
| 前進 | PWM（20kHz） | L | 正転、PWM がオフの間は惰性 |
| 後進 | L | PWM（20kHz） | 逆転、同上 |
| ゼロ | L | L | ストップ（1ms でスタンバイに入り、最大 30µs で復帰） |

- ESP32 から1輪あたり2本、両方を LEDC（PWM）のチャネルにする。3輪で6本。LEDC の低速モードは8本あるので足りる。
- **「PWM 1本＋向き1本」で IN1/IN2 につなぐと壊れた動きになる。** たとえば「前進・指令ゼロ」が (L, H) = 全速逆転になる。
  旧ファームは最初この形だったので、案B に作り直した。
- 外付けロジック（74HC00 で変換）や「後進のときだけデューティを反転」も考えたが、部品が増える・前進と後進で減速の仕方が違う、
  という理由で採らなかった。
- 起動直後は IC 内部の 100kΩ プルダウンで IN1/IN2 が L になるので、ESP32 がリセット中でもモータは止まっている。

### `OUT1` / `OUT2`（赤・白）は GND ではない

「モータ電源 +/−」という呼び名は回す向きを表しているだけで、どちらも H ブリッジが駆動する出力である。
**逆転中は白に 12V が出る。白にエンコーダの黒をつなぐと、逆転した瞬間にエンコーダが壊れる。**

## 4. 電流の守り

**IC 側では電流を制限しない**（RS を GND へ直結、VREF に 3.3V）。机上ではすべて**安定化電源の電流制限（CC）**で守る。

| 段階 | 電源 | 守り |
|---|---|---|
| 机上の確認すべて | 安定化電源 | 電源の電流制限。通常 1.5A |
| 床で走らせる段階 | LiPo | **電流制限が無い。** ソフトのモータロック保護が守りになる |

センス抵抗を入れなかった理由:

- 手に入りやすい 1Ω を1本付けると上限が 0.33A になり（`0.1 × 3.3V / 1Ω`）、モータが走らない。
- その上限ではチョッパがほぼ常に働き、デューティと出力の関係が崩れる。素の挙動なのか制限が効いているのか区別できなくなる。
- 推奨値の 0.22Ω（上限 1.5A）は手に入りにくい。電源側で同じ守りが掛かるなら、部品を増やす理由が無い。

発熱: ストール 2.3A を**流し続けると** 2.3² × 0.6Ω ≒ 3.2W で、許容損失 2.85W（4層基板での値。2層のモジュールではもっと小さい）を超える。
電流制限 1.5A なら約 1.35W。一瞬のストールは熱容量が吸収する。
**LiPo へ移る前に、ソフトのモータロック保護が働くことを確かめる。** 過熱保護（TSD）はデータシートが「積極的に使わないこと」と書いているので頼らない。

| 守りの段 | 働き | 解除 |
|---|---|---|
| 電源の電流制限（机上） | 設定値で頭打ち。電圧が下がるので目で分かる | — |
| ソフトのモータロック保護 | ストールが一定時間（目安 100〜200ms）続いたら止める | ファームの判断 |
| ISD（過電流、標準 4.9A） | 短絡などの異常時にラッチ | 電源の入れ直し、または IN1/IN2 を 1ms 以上 L |
| TSD（150〜175℃） | 最後の砦 | 頼らない |

## 5. ESP32 のピン割当

classic ESP32（ESP32-WROOM-32、PSRAM なし）。次の端子を避けて選んだ。

- ストラッピング端子 0 / 2 / 5 / 12 / 15
- 内蔵フラッシュ用 6〜11
- USB シリアル（書き込みとログ）の 1 / 3
- 入力専用 34 / 35 / 36 / 39（出力には使えない。エンコーダにも内部プルアップが使えないので避けた）

| 用途 | 輪 | GPIO | つなぐ先 |
|---|---|---|---|
| エンコーダ A相 | 0 | 4 | M0 の黄か緑（未確定） |
| エンコーダ B相 | 0 | 13 | M0 の緑か黄（未確定） |
| モータ出力 A | 0 | 19 | U1 IN1 |
| モータ出力 B | 0 | 23 | U1 IN2 |
| エンコーダ A相 | 1 | 14 | M1 |
| エンコーダ B相 | 1 | 16 | M1 |
| モータ出力 A | 1 | 21 | U2 IN1 |
| モータ出力 B | 1 | 25 | U2 IN2 |
| エンコーダ A相 | 2 | 17 | M2 |
| エンコーダ B相 | 2 | 18 | M2 |
| モータ出力 A | 2 | 22 | U3 IN1 |
| モータ出力 B | 2 | 26 | U3 IN2 |
| バッテリ電圧 | — | 32 | `VBAT_SENSE`（ADC1） |
| 机上確認用つまみ | — | 33 | VR1 のワイパ（ADC1） |

- ADC は ADC1 の端子を使う。ADC2 は Wi-Fi を使っているあいだ読めない。
- エンコーダは PCNT（パルスカウンタ）3ユニットで数える。
- 旧ファームではモータ出力を `kMotorPwm` / `kMotorDir` と呼んでいたが、案B では2本とも PWM なので名前と中身が合っていなかった。
  新しく書くときは中立な名前（A / B、IN1 / IN2 など）にする。

## 6. 接地

**2系統に分けて、合流は `GND-STAR` の1点だけにする。**

| 系統 | 流れる電流 | 含むもの |
|---|---|---|
| 動力 `PGND` | 最大 約6.9A（2.3A × 3、ストール時） | LiPo(−)、U1〜U3 の GND、C1/C2 の (−)、U4 の入力 GND |
| 信号 `SGND` | 数百 mA | ESP32 の GND、エンコーダの黒 ×3、C6、VR1 |

```
        LiPo XT60(−)
             |
        +----+---- GND-STAR ----+     ← 1箇所だけ（C1 の (−) 端子を中心にする）
        |                       |
   [ 動力 ]                 [ 信号 ]
   U1/U2/U3 GND             U4 出力 GND → ESP32 GND
   C2 (−)                   → エンコーダ GND ×3 / C6 / VR1
   U4 入力 GND
```

- **確かめ方**: エンコーダの黒から ESP32 の GND ピンまで指でたどり、途中にモータ電流が流れる区間があれば誤り。
- 信号の GND を、動力電流が流れる線の途中にぶら下げない（数珠つなぎにしない）。
- 合流点が2つ以上あると接地ループになる。
- 怖いのは DC の電位差より PWM の切り替わりで立つスパイク。20cm の線で約 200nH、1A/µs なら 0.2V。
  PCNT はエッジを数えるので、**スパイク1発がカウント1個の誤りになる。壊れずに静かに数え間違える。**
- ドライバの GND は動力と論理で共通なので、IN1/IN2 の基準は動力側の電位になる。ESP32 側との差（例: 20mΩ × 2.3A = 46mV）が
  論理のしきい値に比べて十分小さいことが前提。通電確認で測る（[circuit-bringup.md](./circuit-bringup.md) の TP7）。

## 7. ノイズ対策部品と置き場所

置き場所を外すと、つながりが正しくても効かない。

| 部品 | つなぐところ | 置き場所 |
|---|---|---|
| C1 1000µF 電解 | `VM` − `GND-STAR` | 分岐の入口。`GND-STAR` の中心を兼ねる |
| C2 1000µF 電解 | `VM` − `PGND` | 分岐の末端のドライバ（U3）の VM/GND のすぐ近く |
| C3〜C5 0.1µF | 各モータの赤 − 白 | **モータ本体の端子に直付け**（ドライバ側ではない）。モータ1個に1個 |
| C6 0.1µF | `VBAT_SENSE` − `SGND` | **ESP32 の GPIO32 のすぐ近く**（分圧抵抗側ではない） |
| C7〜C9 0.1µF | 各ドライバの VM − GND | **IC のすぐ横** |
| C10〜C12 0.1µF | 各ドライバの VREF − GND | VREF 端子のすぐ近く |

- 電解とセラミックは両方要る。電解は高い周波数に応答できず、スイッチングのエッジはセラミックが受け持つ。
- アプリケーションノートの電解の推奨は 47〜100µF。1000µF はバッテリバスのバルク（回生電流の受け皿）としてわざと大きくしている。
- VM と GND のループ面積を小さくする。長い線の先にコンデンサを置いても効かない。

## 8. 極性に注意する部品

| 部品 | 間違えると |
|---|---|
| C1 / C2 電解 | **逆に付けると破裂・発火する。** 本機でいちばん危ない。(+) を `VM` 側へ |
| BP5293-50 | 入力 / GND / 出力の並びを間違えると壊れ、5V が出なくなる |
| U1〜U3 の VM / GND | 逆につなぐとドライバが壊れる |
| モータの赤 / 白 | 入れ替えると回転が逆になるだけ。壊れない |
| XT60 | 形で逆挿しできない |

## 9. 電圧の測定点

| TP | 場所 | 基準 | 期待値 |
|---|---|---|---|
| TP1 | F1 の出力（`VM`） | `GND-STAR` | 11.1〜12.6V（安定化電源なら設定値） |
| TP2 | U4 の出力（`+5V`） | `GND-STAR` | 5.0V ±5% |
| TP3 | ESP32 の `3V3` | `SGND` | 3.3V ±5% |
| TP4 | `VBAT_SENSE`（GPIO32） | `SGND` | **3.3V 未満**（12.6V のとき約 2.68V）。ESP32 をつなぐ前に測る |
| TP5 | エンコーダコネクタの青 | エンコーダの黒 | **3.3V。12V が出ていたらすぐ止める**。エンコーダを挿す前に測る |
| TP6 | U1〜U3 の VM 端子 | `GND-STAR` | TP1 との差が 0.2V 未満 |
| TP7 | U1 の GND 端子 | `SGND` | 無負荷でほぼ 0V。負荷時の差を記録する |

## 10. まだ決まっていないこと

| 事項 | 決め方 |

| エンコーダの A相 / B相 がどちらの色（黄 / 緑）か | 輪を回してカウントの符号を見る。取り違えたまま速度制御を閉じると正帰還で暴走する |
| OUT1 / OUT2 と 赤 / 白 の対応（どちらを正転とするか） | モータ単体を電源に直結して決める |
| メイン電源スイッチ SW1 | 要るか、どこに付けるか、どの形式か。機体の形と一緒に決める |
| 電源分岐端子 TB1 | 要るか、どう分けるか |
| エンコーダの外付けプルアップ（10kΩ × 6） | 出力がオープンコレクタかどうか不明。図には破線で置き場所だけ確保してある。カウントが不安定なら付ける |
| 物理的な非常停止 | 未決 |
| ESP32 の Flash サイズ設定 | 旧ファームのビルドで「Expected 4MB, found 2MB」の警告が出ていた。→ [dev-environment.md](./dev-environment.md#flash-サイズの警告未対応) |
