# トライアル計画（たたき）

本番用のソースを書く前に、**捨てる前提の試作**で、実物を触らないと分からないことを先に分かっておく。
ここに書いたのは叩き台である。順番も中身も、やりながら変えてよい。

## 1. 進め方の約束

- **トライアルごとに「何を確かめるか」を先に書く。** 答えが出たらそこで止める。磨かない。
- **コードは使い捨てでよい。** テストや設計の整理はしない。動かして結果を見ることを優先する。
- **記録は残す。** 何をして、何が起きて、いくつだったか。写真と数値をそのまま。
- **想定値はトライアルの結果で置き換える。** [overview.md](./inherited/overview.md) の時間予算、[hardware.md](./inherited/hardware.md) の公表値など。
  ただし `inherited/` の文書は引き継いだ時点の記録として書き換えない。分かったことは `docs/` の直下に新しく書き、
  どの想定値を置き換えたかが分かるように元の文書へのリンクを付ける。
- 安全の約束だけはトライアルでも守る: 初通電は電流制限つきの安定化電源で行う、最初はホイールを浮かせる、
  デッドマンと指令途絶での停止を入れてから走らせる。

### 記録の置き場所（案）

```
trials/
  01-circuit/        notes.md、写真、測った値、使い捨てのファーム
  02-trash-bin/
  03-mobile-base/
  04-fixed-side/
  05-simulation/
  06-integration/
docs/                トライアルで分かったことを反映していく
  inherited/         旧リポジトリから引き継いだ文書。書き換えない
```

## 2. 全体の順番

```
                    すぐ始められる
  [05 シミュレーション] ─────────────┐
  [02 ゴミ箱]          ─────────────┤
  [04 固定側]  Pi と D435 は準備済み ┤
                                     │
  [01 回路] ──→ [03 移動体] ─────────┤
   安定化電源が要る                   ↓
                              [06 結合]
```

- 05・02・04 は今の手持ちだけで始められる。01 は安定化電源があるかの確認から。
- 03 は 01 で1輪ぶんの回路が動いてから。
- 06 は 03 と 04 がそれぞれ単独で動いてから。

## 01 回路

**目的**: 回路図のたたき台どおりに組んで、1輪 → 3輪と動かし、実物に合わせた回路図を新しく起こす（たたき台そのものは直さない）。

**最初の一歩**: 安定化電源・可変抵抗が手元にあるか確かめる。ブレッドボードかユニバーサル基板に1輪ぶんを組み、
[circuit-bringup.md](./inherited/circuit-bringup.md) の E-0 から順に進める。

**回路図を作る順番**: 3段階に分け、段階ごとに回路図を残す（前の段階を上書きしない）。
KiCad プロジェクトは `trials/01-circuit/kicad/mobile-base/` に置く。PCB は作らず、ユニバーサル基板で組む。

| 段階 | 回路図の中身 | 対応する立ち上げの段 |
|---|---|---|
| 1. モータ単体の動作確認 | ESP32 を使わず、電源とモータ1個で回るかを確かめる回路 | E-1, E-2 |
| 2. 1輪ぶんの動作回路 | 1 に ESP32・ドライバ・エンコーダを足し、ESP32 から1輪を動かす回路 | E-3〜E-6 |
| 3. 3輪ぶんの回路 | 2 を3輪に広げた完成形 | E-7 |

- 段階1にドライバを入れるか（E-2 はドライバを通さずにモータを回す段）は、段階1の回路図を描く前に決める。
- 段階を進めるのは、前の段階の回路で実物が動いてからにする。

**確かめること**

| 問い | どの段で分かるか |
|---|---|
| IN1/IN2 を両方 PWM にする動かし方（案B）が期待どおりか | E-3（LED） |
| ドライバはどのくらい熱くなるか。電流制限 1.5A で足りるか | E-4 |
| モータ3個の無負荷電流は揃っているか。外れ値の個体は無いか | E-2 |
| 3.3V でエンコーダのカウントは安定するか。外付けプルアップは要るか | E-6 |
| A相 / B相 はどちらの色か。出力軸1回転あたりのカウントはいくつか | E-6 |
| DualSense を ESP32 へ Bluetooth で直接つなげるか。遅れは実用になるか | E-5 |
| ESP32 の ADC でバッテリ電圧をどのくらいの精度で読めるか（テスターと比べて係数を決める） | E-1 以降 |
| モータを回したときに GND の電位差やスパイクでカウントが乱れないか | E-6, E-7 |
| USB と BP5293-50 の切り替え（JP1）で困らないか | 全段 |
| ESP32 の Flash サイズ設定（4MB と 2MB の食い違い）で書き込みに問題が出ないか | 最初の書き込み |

**終わりの目安**: 3輪とも机の上で回り、コントローラで1輪ずつ選んで回せて、エンコーダのカウントが取れる。
実物と一致する段階3の回路図が KiCad にあり、書き出したものが `docs/` の直下にある（たたき台は [circuit/schematic-draft.html](./inherited/circuit/schematic-draft.html)）。

**決めること**: メイン電源スイッチ・電源分岐端子の要否と形、非常停止の手段（03 と一緒に）。

## 02 ゴミ箱

**目的**: 受け口として「入る」だけでなく「留まる」かを確かめ、対象にするゴミと許容誤差を決める。

**最初の一歩**: 手元の山田化学 No.335 を測る（開口の内径、高さ、底の径、テーパー、重さ、縁の形）。
旧リポジトリでの採寸値（[参考値](./inherited/reference-measurements.md#4-ゴミ箱山田化学-no335)）と比べる。

**確かめること**

| 問い | やり方 |
|---|---|
| 何を投げる対象にするか（空き缶、ペットボトル、丸めた紙など） | 候補を実際に落とし入れて、跳ね出す率を見る |
| どの高さ・角度から入ると跳ね出すか | 1m 程度の高さから、中心・縁寄りに落とす |
| 底や側面に緩衝材を入れると跳ね出しが減るか。何を入れるか | タオル・スポンジ・発泡材などで比べる |
| 縁にかかったものはどうなるか。中心からどこまでずれて入れば成功か | 中心からの距離を変えて落とす |
| 漏斗やワイドリムで実質の開口を広げる価値があるか | 段ボールなどで仮に作って比べる |

**終わりの目安**: 対象のゴミが決まり、「中心から ±何 mm に入れば留まる」が数字で言える。緩衝材の要否が決まる。

## 03 移動体

**目的**: 3輪オムニの足回りを最小構成で組み、手動で走らせ、短時間にどれだけ動けるかを測る。

**最初の一歩**: モータ・ブラケット・ハブ・ホイールを1組仮組みして測る（実効径、最低地上高、ブラケットの穴、
イモネジが D カットの平面に当たっているか）。旧リポジトリでの採寸値（[参考値](./inherited/reference-measurements.md#2-駆動ユニット)）と比べ、
特に「取付面 → ホイール中心」を測った向きを確かめる。土台は造形を待たず、板（MDF・アクリル・段ボールでもよい）に穴をあけて作ってもよい。

**確かめること**

| 問い | やり方 |
|---|---|
| ブラケットの穴2つ（M3 × 2本）で駆動ユニットを保持できるか | 組んで手で揺する、急加速・急停止を繰り返す |
| 床に何も擦らないか（ブラケット・ボルト頭・配線） | 組んで目で見る、走らせる |
| 3輪の向きと符号が合っているか（前に倒してまっすぐ進むか） | 台の上 → 床の上で手動走行（→ [circuit-bringup.md](./inherited/circuit-bringup.md#床に置いてからの確認参考)） |
| デッドマン解放・コントローラ断で止まるか。ロック保護が働くか | わざと起こす |
| **静止から 0.4 / 0.6 / 0.9 秒で何 m 動けるか** | 手動ではなく、決まった指令を流すスクリプトで測る。動画で撮ると楽 |
| 発進でスリップするか。急停止で転びそうか | ゴミ箱を載せた状態で |
| 加速時にバッテリ電圧がどこまで下がるか | 低電圧保護の閾値を決める材料 |
| 手動で正方形を走ってどのくらいずれるか | オドメトリのずれ |
| 実効径・エンコーダの値でオドメトリの距離が合うか | 巻尺で測った距離と比べる |
| 全体の重さと重心 | 量る |

**終わりの目安**: ゴミ箱を載せて手動で走れる。0.4 / 0.6 / 0.9 秒の移動距離が出ている。

## 04 固定側

**目的**: 投げた物を D435 と Pi 4 で捉え、落下地点を予測できるか、そして時間予算が成り立つかを確かめる。

**最初の一歩**: Pi 4 に D435 をつなぎ（[dev-environment.md](./inherited/dev-environment.md#3-raspberry-pi-4)）、空き缶を投げて Depth を記録する。
まず記録だけ取り、検出と予測は開発PC で記録を再生しながら試す。

**確かめること**

| 問い | やり方 |
|---|---|
| どこにカメラを置くか（壁・三脚、高さ、向き） | いくつか置いて、投擲の軌跡が視野に入るか見る |
| 30fps / 60fps のどちらが要るか。Pi 4 で何 fps 出るか | 解像度と fps を変えて測る。電圧低下（`vcgencmd get_throttled`）も同時に見る |
| 一番軽い検出方法で空き缶が取れるか（Depth の範囲・背景差分・フレーム間差分） | 記録を再生して比べる |
| **手を離してから検出が始まるまで何秒か** | 一番根拠の無い想定値。手や腕に隠れる時間を含めて測る |
| 何点取れたか。何点で予測が落ち着くか | 予測を点数ごとに出して、実際の落下地点と比べる |
| 予測した落下地点・時刻は実際とどのくらいずれるか | 床に印を置き、動画で落ちた位置と時刻を取る |
| 人が投げたとき、横方向のずれ（必要な横移動）はどのくらいか | 同じ人が同じ場所に向けて何回も投げる |
| 床と座標系をどう決めるか。既知の点に置いた物の座標が合うか | 床の平面を当てはめ、印を置いて確かめる |

**終わりの目安**: 時間予算の表（[overview.md §3](./inherited/overview.md#3-難しいところ-時間予算)）を測った値で作り直せる（新しい表は `docs/` の直下に置く）。
予測誤差と必要な横移動量が数字で出ている。

## 05 シミュレーション

**目的**: 投げ方（位置・方向・距離）をどう決めれば成り立つかを机の上で見積もり、移動体に要る性能を数字にする。

**最初の一歩**: スプレッドシートか短い Python で十分。

1. 投げる距離と高さから飛行時間を出す（放物運動、空気抵抗なし）。
2. 飛行時間から遅れ（今は想定 0.2〜0.3s）を引いて、移動体が使える時間を出す。
3. 移動体を「加速度の上限＋最高速度」で近似し、使える時間で動ける距離を出す。
4. 必要な横移動量と比べて、間に合う／間に合わないを図にする（横軸: 使える時間、縦軸: 必要な横移動量）。

**確かめること**

| 問い | 入力をどこから持ってくるか |
|---|---|
| どの投げ方なら、今の足回りで間に合うか | 加速度・最高速度は最初は仮の値 → 03 の測定で置き換える |
| 目標で止まって待つのと、通過しながら受けるのとで、どのくらい差があるか | 減速も同じ加速度で近似する |
| 遅れが 0.1s 増えると、成り立つ範囲はどのくらい縮むか | 04 の測定で置き換える |
| 位置の許容誤差が変わると、どのくらい効くか | 02 の測定で置き換える |

**守ること**: モデルに入れていない要因（空気抵抗、跳ね出し、スリップなど）と、各値が仮か実測かを図に書いておく。

**終わりの目安**: 「この投げ方なら、移動体は 0.6 秒で何 m 動ければよい」が言える。投げ方の案が1つに絞れている。

## 06 結合

**目的**: 予測 → 通信 → 走行をつないで、短い距離で一度受け止めてみる。

**前提**: 03 と 04 がそれぞれ単独で動いている。動作領域の制限と、通信が途絶えたら止まる処理が入っている。物理的な非常停止がある。

**確かめること**

| 問い | メモ |
|---|---|
| 固定側から移動体へ何で送るか（Wi-Fi UDP、固定側に置いた ESP32 で中継、など） | テレオペ用の Bluetooth とは別のビルドになる |
| 送ってから動き出すまで何秒か | 時間予算の3つ目の区間 |
| 座標系がずれていないか | 既知の位置にゴミ箱を置いて、固定側の座標と比べる |
| まず投げずに、手で持った物をゆっくり動かして追従するか | 投げる前の段階 |
| 投げ方を固定し、横移動を小さくして、受け止められるか | 成功率を数える |

**終わりの目安**: 決めた投げ方で、何回かに1回は受け止められる。成功率の目標と試行回数 N を決める材料が揃う。

## 3. トライアルを終えて本番へ進む目安

次に答えられるようになったら、本番用のソースに取りかかる。

- 回路図が実物と一致し、3輪が保護つきで回る
- 対象のゴミ、ゴミ箱、位置の許容誤差が決まっている
- 移動体が 0.4 / 0.6 / 0.9 秒で動ける距離が分かっている
- 時間予算の各区間が測った値になっている
- 投げ方が決まり、シミュレーションで成り立つ範囲が分かっている
- 一度でも受け止められている（または、受け止められない理由が分かっている）
- 固定側と移動体の通信方式が決まっている

本番でどこまで仕様を書くかは、そのときに決める。
