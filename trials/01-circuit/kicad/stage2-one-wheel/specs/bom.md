# BOM: stage2-one-wheel（段階2 1輪ぶんの動作回路）

計画: [trial-plan.md の 01 回路](../../../../../docs/trial-plan.md#01-回路)。元の資料: [circuit.md](../../../../../docs/inherited/circuit.md)、
[circuit-bringup.md](../../../../../docs/inherited/circuit-bringup.md)、[hardware.md](../../../../../docs/inherited/hardware.md)。
前の段階: [stage1-motor の bom.md](../../stage1-motor/specs/bom.md)（E-1 ①・E-2 合格。結果は [notes.md](../../../notes.md)）。

## 範囲

- 段階1の電源の入口（J1・F1・C1）に、5V 電源（U4 BP5293-50）、ESP32（U5）、ドライバ（U1 AE-TB67H450）、モータ M0 のエンコーダ、
  机上確認用のつまみ（VR1）、バッテリ電圧の分圧（R1・R2・C6）を足した、輪0（モータ M0）1輪ぶんの完成形。
- circuit.md に無い部品を3つ足す: 回生の電圧を抑える TVS（D3）、エンコーダの信号線の保護抵抗（R10・R11）。理由は「保護」。
- LED 治具（D1・D2・R9・J4）も同じ図に描く。モータの代わりに J2 へ挿す、別の小さな回路として描き、ほかとは線でつながない。
- 入れないもの:
  - 輪1・輪2（U2・U3・M1・M2）。
  - C2（2個目の 1000µF）。circuit.md では分岐の末端のドライバ（U3）の横に置く部品。1輪だけなら C1 を U1 の横に置けば同じ役目になる（C1 の Notes）。段階3で足す。
  - 主電源スイッチ SW1・電源分岐 TB1（段階3で決める）。
  - U4 の入力ヒューズ F2（データシートが 3A 以下を求める）。机上は安定化電源の制限 1.0A 以下が同じ役目をする。**LiPo につなぐ前（段階3）に足す**（「保護」）。
  - エンコーダの外付けプルアップ R3〜R8（ESP32 の内部プルアップで始め、カウントが不安定なときだけ足す。circuit.md の「まだ決まっていないこと」）。
    **足すときは R10・R11 の J3 側（`ENC0_A`・`ENC0_B`）に付ける。** ESP32 側（`ENC0_A_IN`・`ENC0_B_IN`）に 10kΩ を付けると、
    エンコーダが L を出しても 3.3V × 4.7k ÷ (10k + 4.7k) ≒ 1.06V になり、L と読める上限 0.83V を超えて数えられなくなる。
- 部品番号は [circuit.md](../../../../../docs/inherited/circuit.md) とたたき台に合わせる（U1、U4、C1、C3、C6、C7、C10、R1、R2、VR1、JP1、TP1〜TP7、M0）。
  circuit.md に番号が無いものは新しく振る（U5 ESP32、NT1、J2〜J4、D1〜D3、R9〜R11）。段階3で同じ番号を使い続けるため。

## Constraints

- 入力: 机上は安定化電源 12.0V（段階1と同じ。XT60 のケーブルで J1 へ）。設計上の上限は LiPo 3S 満充電の 12.6V
- ESP32 の電源: 書き込み・ログ・モータを回すあいだは USB（JP1 を外す）。U4 からの給電は H で確かめるだけ（下の「組む順番と電流制限」）
- 組み方: ブレッドボード（持ち主の回答）。ESP32 は2枚のブレッドボードにまたがせる。PCB は作らない
- フットプリント: **割り当てない**（CLAUDE.md の決まり）。Layers / IPC class / Manufacturer min trace: 対象外
- 電流: モータ1個。無負荷 0.15〜0.17A（E-2 で測った値）、ストール 約 2.3A。安定化電源の電流制限で頭打ち
- Thermal: 室内、机上、ケースなし、自然空冷
- EMI/EMC: 規格の要求なし。ブラシノイズは C3、ドライバのスイッチングは C7・C1 で抑える。接地は `PGND` と `SGND` を1点（`GND-STAR`）で合わせる

### 記号の変更（自作ライブラリ）

- 新しく作った: `ESP32-DevKitC-38`、`AE-TB67H450`、`BP5293-50`（KiCad の標準ライブラリに classic ESP32 の DevKitC・このドライバモジュール・BP5293 が無い）。
- 電源の**入力側**のピン（ドライバの VM・GND、BP5293 の VIN・GND、ESP32 の 5V・GND）は種類を `passive` にした。
  `power_in` にすると、ERC が「電源の出どころ」を求め、PWR_FLAG（部品番号 `#FLG` が図に出る）を置くことになるため。
  出力側（BP5293 の VOUT、ESP32 の 3V3）は `power_out` にしたので、`+5V` と `+3V3` に出どころがあることは ERC が確かめる。
- `JGB37-520` の pin4（エンコーダの黒）を `power_in` から `passive` に変えた。段階2で `SGND` につなぐと、`SGND` には出どころが無いため。
  番号・名前・位置は変えていない。ライブラリのファイルにはこの記号しか無かったので、ファイルを作り直した。
  段階1の回路図は記号の写しを中に持っているので変わらない（pin4 は未接続の印のまま）。
- D3 は標準の TVS の記号（`D_TVS` は双方向、`Diode:1.5KExxA` はピン名が A1・A2 でどちらがカソードか読めない）ではなく、
  `Device:D_Zener`（ピン名 K・A）に値 `P6KE18A` を入れて描く。単方向の TVS はツェナーダイオードと同じ形で働く。

| C | ＋J3（エンコーダ）。R10・R11 があれば入れる（12V が無いので無くてもよい）。モータの軸は手で回す | USB | — | TP5 が 3.3V（E-1 ⑥）、カウント、A相の色、1回転のカウント（E-6 の一部） |
| D | 配線なし。DualSense をつなぐ | USB | — | ペアリング、遅れ（E-5 の一部） |
| E | J1・F1・C1・NT1・U4、R1・R2・C6（GPIO32 にはまだつながない） | 安定化電源 | 0.2A | TP1、TP2 5V（E-1 ②）、TP4 が 3.3V 未満（E-1 ④） |
| F | ＋U1・C7・C10、LED 治具を J2 へ。U5 は USB のまま（JP1 外す） | USB ＋ 安定化電源 | 0.5A | TP6・TP7（E-1 ⑤）、LED（E-3） |
| G | **D3・R10・R11 を入れてから**、治具を外して M0 を J2 へ | 同上 | 0.5A → 1.0A | 0.5A で止まっていること（E-1 ⑦）。1.0A に上げて開ループ（E-4）、エンコーダとコントローラ（E-6） |
| H | **M0 を J2 から外し**、GPIO32 をつなぐ。① USB のまま ② USB を抜き、JP1 を挿す | ① USB ＋ 安定化電源 ② 安定化電源 | 0.2A | ① 電池電圧の読み ② TP3（E-1 ③） |

- 一つずつの手順（配線、電源を入れる前のテスターでの確認、測る値）は [stage2-procedure.md](../../../stage2-procedure.md)。
- H を2つに分けた（2026-11-11）。電池電圧の読みはシリアルモニタで見るので、USB を抜く前に行う。
- **E-4・E-6 の電流制限を 1.5A から 1.0A に下げる**（circuit-bringup.md は 1.5A）。段階1と同じ理由で、ブレッドボードの接点の定格（製品によって 1A 前後〜3A）に合わせる。
  無負荷電流は 0.17A なので回すには足りる。回り始めの一瞬だけ 1.0A で頭打ちになる。1.0A に張り付いたままなら止める。
- **モータを回すのは ESP32 を USB で動かしているとき（G）だけにする。** ESP32 を U4 から動かしたまま（H）モータを回すと、回り始めや軸が止まったときに
  電流制限 1.0A に張り付き、VM が 1.0A × (5.2Ω + 0.6Ω) ≒ 5.8V まで下がる。U4 は VIN が 6.4V（6.0〜6.8V）を下回ると止まるので（ROHM データシート）、
  ESP32 がリセットする。モータは止まる側なので危なくはないが、原因が分かりにくい。U4 から動かしたまま回すのは、電圧が下がらない LiPo に移ってから（段階3）。
- **モータを逆転させる指令（E-6 で DualSense のスティックを逆に倒す、など）は D3 を入れてから。** ファームは、指令の符号が変わるとき
  いったん止める（IN1・IN2 とも L）にして、エンコーダの速さがほぼ 0 になってから逆へ出す（「保護」の回生）。
- USB と安定化電源を同時につなぐとき（F・G）、ESP32 の GND は PC の GND につながる。安定化電源の出力は − 端子が浮いているのでつないでよい。
  **安定化電源の緑の GND 端子は使わない**（ケースのアース。段階1で分かったこと）。
- 電源を入れる順番: ESP32 をリセットしてから（または USB で動かしてから）VM を入れる（circuit-bringup.md の決まり）。

## 計算と根拠

- **U4 の負荷**: ESP32 の Bluetooth 送信のピーク 約130mA ＋ ボード 約20mA ＋ エンコーダ1個 約15mA ≒ 0.17A（circuit.md の3個ぶんの見積もり 約0.3A を上限に使う）。1A に対して 30% 以下。
- **U4 の入力コンデンサ**: データシートでは、入力・出力のコンデンサはモジュールに内蔵されている。外付けの入力コンデンサは不要で、
  配線が長いときや入力電圧が大きく揺れるときに VIN の近くに足すことをすすめている。C1（1000µF）を U4 の横に置いてこれを兼ねる。
  モータを回すと TP2 が揺れる（5V ±5% を外れる）ときは、データシートの推奨値の 10µF セラミック（耐圧 50V。D3 が VM を 20V 前後に抑えるので 35V でも足りる）を
  VIN − GND のすぐ近くに足す。手元に無いので、そのときに買う。
- **U5 の 3V3**: (5 − 3.3)V × 0.3A ≒ 0.5W が基板上のレギュレータの熱になる（circuit.md）。温かくなるが故障ではない。
- **分圧（R1・R2）**: 22 ÷ (100 + 22) = 0.1803。12.0V → 2.16V、12.6V → 2.27V、9.0V → 1.62V。満充電でも 3.3V 未満。
  - classic ESP32 の ADC（減衰 11dB）がまっすぐ読めるのは 約 2.45V まで（ESP-IDF の資料）。22kΩ なら 12.6V でもこの範囲に入る（電池側で 13.6V まで）。
  - 守りたい低い側（放電の終わり、約 9.9〜10.5V → 1.79〜1.89V）も読める。1目盛り（約 0.8mV）は電池側で約 4.4mV で、細かさは足りる。テスターと突き合わせて係数を決める（circuit.md）。
  - circuit.md は 27kΩ だが、手元に無い（持ち主の回答 2026-11-14。あるのは 22kΩ・33kΩ）。33kΩ は 12.6V で 3.13V になり、2.45V を超えるうえ 3.3V までの余裕が 0.17V しかないので使わない。
  - R2 が外れると GPIO32 に 100kΩ を通して 12V がかかるが、流れるのは (12 − 3.6)V ÷ 100kΩ ≒ 84µA。
- **D3（TVS）**: 逆方向の動作電圧 15.3V は LiPo 満充電 12.6V より上なので、ふだんは流れない（漏れ電流は数 µA 以下）。
  回生で VM が上がると 17.1〜18.9V で流れ始め、数 A でも 20V 前後に抑える。U4 の入力の上限 26V、C1 の 35V より下。
  - 回生の電力のピーク: 逆向きの PWM を掛けたとき、E²/(4R) = 11.1V² ÷ (4 × 5.2Ω) ≒ 6W（デューティ 約 27% のとき）。E は無負荷の逆起電力、R はモータの巻線の抵抗（12V ÷ 2.3A）。
  - 戻るエネルギー: 回っているロータと輪の運動のエネルギーで、推定 0.1〜0.3J。ロータの慣性はデータが無く仮定した値なので、数倍ずれることもありうる。
  - C1 が先に受ける分: D3 が流れ始める 17V までに ½ × 1000µF × (17² − 12²) ≒ 73mJ。
  - D3 が受ける分: 残り 0.25J 以下を数十 ms かけて受ける。平均で数 W で、P6KE18A の定常の許容 5.0W 以下。600W は 1ms 程度の短いパルスの値なので、ここでは定常の値と比べる。
  - ふだんは、ファームが逆転の前に止めて待つので回生はほとんど起きない。D3 はファームの誤りへの備え。
  - エネルギーの推定に幅があるので、余裕を大きくしたいときは 1.5KE18A（1500W、定常 6.5W）。ただし足が太く（約 1mm）、ブレッドボードには挿しにくい。P6KE18A の足（約 0.8mm）は挿せる。
- **R10・R11**: 12.6V の線を間違えて挿したとき (12.6 − 3.6)V ÷ 4.7kΩ ≒ 1.9mA。ESP32 の内部プルアップ（約 45kΩ、少なく見て 30kΩ）とエンコーダが L を出したときの電圧は
  3.3V × 4.7 ÷ (4.7 + 30) ≒ 0.45V で、L と読める上限（0.25 × 3.3V ≒ 0.83V）より下。エンコーダの信号は 約 1.8kHz（11 パルス × 約 10000rpm ÷ 60）で、
  4.7kΩ とピンの容量（数十 pF）で遅れるのは 1µs 以下なので数え落とさない。
- **VREF**: 3.3V（データシートの範囲 1〜5V、絶対最大 5.5V）。RS を GND へ直結して定電流制御を切る（circuit.md）。
- **IN1・IN2**: H レベル 2.0V 以上なので ESP32 の 3.3V で動く。内部の 100kΩ プルダウンで、ESP32 のリセット中は L（モータは止まる）。
- **LED 治具**: (12V − 2V) ÷ 1kΩ ≒ 10mA。
- **電圧の余裕**: C7・C3 25%、C1 36%、U1 29%（12.6V ÷ 44V）、U4 48%（12.6V ÷ 26V）。

## 保護

| 何から | どう守るか | 守らないもの・その理由 |
|---|---|---|
| 過電流・短絡（机上） | 安定化電源の電流制限（0.2A → 0.5A → 1.0A） | U1 の電流制限は使わない（circuit.md。RS を GND に直結） |
| 短絡（LiPo につないだ後） | F1 10A | 段階2では LiPo を使わない |
| U4 が壊れて VIN と VOUT が短絡し、大きな電流が流れ続ける | 机上は安定化電源の制限（最大 1.0A。データシートが求める 3A 以下のヒューズと同じ役目） | **F2（3A 以下、たとえば 1A）を U4 の VIN の手前に、LiPo につなぐ前（段階3）に足す**。データシートは「3A 以上が流れ続けると発煙・発火のおそれ」と書いている |
| 回生（モータを逆転させたり急に止めたりしたとき、モータの運動のエネルギーが電源へ戻り、VM が上がる） | D3（TVS）で 20V 前後に抑える。ファームは逆転の前に止めて待つ | 安定化電源は電流を吸い込めないので、戻った分は C1 に溜まって VM が上がる。D3 が無いと U4 の上限 26V や C1 の 35V を超えうる。前進だけ（E-3・E-4）なら回生しないので、D3 は G の E-6 の前でよい |
| 逆接 | XT60 の形。安定化電源側はテスターで確かめた | 逆接防止の部品は入れない（段階1と同じ理由）。D3 は逆接では順方向に流れ、電源の制限に張り付く（気付ける） |
| USB と U4 の 5V のぶつかり | JP1 を外す | — |
| エンコーダの電源に 12V | J3 の黒を `SGND` へ。TP5 を挿す前に測る | — |
| エンコーダの信号線に 12V（モータの赤・白を隣の列に挿し間違える） | R10・R11 で GPIO へ流れる電流を 約 1.9mA に抑える | 間違えないのがいちばん。モータの6本の線は、赤・白とエンコーダの4本をブレッドボードの離れた所に挿す |
| GPIO32 に 3.3V 以上 | TP4 を GPIO32 につなぐ前に測る | — |
| モータのストールでの発熱 | 机上は電源の制限 1.0A（U1 の損失 1.0² × 0.6Ω = 0.6W） | ソフトのモータロック保護は LiPo に移る前（段階3）に確かめる |
| ESP32 を S3 用の端子台に挿す | 使わない。ブレッドボードに挿す | — |
