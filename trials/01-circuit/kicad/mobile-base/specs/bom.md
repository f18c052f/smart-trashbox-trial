## 範囲

- 段階2の1輪ぶん（輪0）を部品番号・ネット名・値ごと引き継ぎ、次を足した3輪ぶんの完成形。
  - 輪1・輪2: ドライバ U2・U3、モータ M1・M2、0.1µF（C4・C5・C8・C9・C11・C12）、エンコーダの保護抵抗 R12〜R15、差し込み口 J5〜J8。
  - C2（2個目の 1000µF）。電源の入口からいちばん遠いドライバ U3 の横に置く（circuit.md §7）。
  - F2（U4 の入力ヒューズ）。段階2で「LiPo につなぐ前に足す」と決めたもの。
  - C13（U4 の入力コンデンサ 10µF）。F2 を入れると C1 が F2 の向こう側になるので、データシートの推奨どおり F2 の後ろ・U4 の VIN の直近に置く（「計算と根拠」）。
  - SW1（主電源スイッチ。非常停止を兼ねる）と J9（基板の電源の入口の端子台）。2026-11-15 に持ち主の OK（下の「SW1 と電源の分け方」）。
  - **WS2812B（フルカラー LED のテープ）をつなぐ口**: U6（レベル変換）、C14・C15、R16・R17、J10（3P 端子台）。2026-11-19 持ち主の依頼（下の「LED の口」）。
    作業はブランチ `stage3-led` で行い、LED を足す前の段階3はタグ `stage3-done` に残した。
- 段階2から引き継ぐ決めごと: R2 22kΩ と電池電圧の式（notes.md の H-1）、黄が A相、D3・R10・R11、F2。
- 段階2の図から外すもの: LED 治具（D1・D2・R9・J4）。輪1・輪2 の E-3 はテスターで確かめる（notes.md の 2026-11-15「LED 治具は省いてよい」）。
  治具を使うときは段階2の図を見る。
- 描かないもの:
  - エンコーダの外付けプルアップ R3〜R8。段階2の G で、ESP32 の内部プルアップだけで数えられた。足すときは段階2と同じく保護抵抗の J 側（`ENCn_A`・`ENCn_B`）に付ける。
  - 電源の分岐の端子 TB1（circuit.md・清書の WAGO 221）。ドライバ3台を1枚の基板に載せるので要らない（下の「SW1 と電源の分け方」）。
- 部品番号は circuit.md と段階2に合わせる。**欠番**: J4、D1、D2、R9（LED 治具）、R3〜R8（プルアップを足すときの予約）。
  新しく振ったもの: F2、C13、J5〜J9、R12〜R15、TP8・TP9。LED の口で U6、C14・C15、R16・R17、J10。

### SW1 と電源の分け方（2026-11-15 持ち主の OK）

- **SW1 は主電源スイッチと非常停止を1つで兼ねる。** 保護カバー付きのトグルスイッチ（車用、2端子の ON-OFF、直流の定格に **DC24V 10A 以上** の表示があるもの）を F1 のすぐ後ろに入れ、
  ドライバ3台・U4（ESP32）・分圧をまとめて切る。カバーを叩き下ろすとレバーが OFF に倒れるものを選ぶ。機体のどこに付けるかは 03 で決める。
  - 全部を切るので、LiPo で入れ直すと ESP32 が最初から起動し、スティックを中央に戻すまでモータは回らない（g_teleop の決めごと）。
  - 直流の定格があるものにした。直流は交流より火花が消えにくい。ロッカースイッチやきのこ形の非常停止ボタンの多くは、交流の定格だけか、直流 1A 前後の制御回路用。
  - 切るとモータは惰性で止まる（ブレーキはかからない）。ふだん止めるのはファーム（デッドマン、指令の途絶、ロック保護）で、SW1 はそれが効かないときの最後の手段。
- **電源の分岐の端子は使わない。** ドライバ3台・U4・C1・C2・D3 を1枚のユニバーサル基板に載せ、`VM` と `PGND` は基板の上の太い線（母線）で3台に分ける。
  電池からの線は基板の入口の J9（2P 端子台）で受ける。
  - モータの電流が通るつなぎ目が減る（つなぎ目は緩むと熱を持つ）。`PGND` が基板の上で C1 の − 足（`GND-STAR`）に集まり、1点の接地を守りやすい。

### LED の口（2026-11-19 持ち主の依頼）

- **回路は組んでおき、LED は付け外しできるようにする**（持ち主）。LED のテープは J10（3P 端子台）にねじで留める。ふだんは外しておいてよい。
  - LED を外していても、GPIO27 を使わないファーム（i_bench・k_teleop など）はそのまま動く。GPIO27 は R17 で L に保たれ、U6 の出力も L のまま。
  - 手元の LED: 試験用の5個つながったテープと、長いテープ（持ち主）。まず5個のもので確かめる。
- **LED の 5V は U4 から取る**（専用の電源は足さない）。U4 の出力 1A は絶対最大定格（BP p.3。瞬時も超えてはならない）なので、ファームの誤りがあっても超えないように、ハードで数を決める（「計算と根拠」）。
  - **J10 につなぐ LED は 8個まで。** 8個を全部白・最大にしても、ESP32 とエンコーダを合わせて 0.79A（79%）。
    U4 の過電流の制限は出力が 約 1.9A になるまで働かないので、1〜1.9A のあいだはハードで止まらない。数を守るのが守りになる。
  - ふだんはファームで LED の合計を 0.4A 以下に抑え、U4 を 0.7A（70%）以下で使う。
  - 長いテープは **8個に切って**使う。もっと多く付けたいときは、LED 専用の 5V 電源（ヒューズ付き）を足す別の変更になる。
- **信号はレベル変換の IC（U6 SN74AHCT125N）で 5V にする。** WS2812B は 5V で動かすと H と読む下限が 3.5V（0.7 × VDD）で、ESP32 の 3.3V では足りない。
  - **手元の SN74AHC125N（T が無い）は使えない。** AHC は入力の H の下限が 0.7 × VCC（表の値は 3V で 2.1V、5.5V で 3.85V）で、5V で動かすと 3.5V 前後になり、WS2812B と同じく 3.3V を H と読めない。
    TI のデータシートが「3.3V の H では低すぎる」とこの例そのものを書いている（SN74AHC125 SCLS256O §8.2.1）。AHCT は入力が TTL レベル（H の下限 2.0V）で、5V で動かしたまま 3.3V を読める。ピンの並びは同じ。
- 信号は **GPIO27** から出す。空いているピンのうち、起動のしかたを決めるピン（0・2・5・12・15）でも入力専用（34〜39）でもないのは 27 だけ。
- `PGND` と `SGND` の分け方を守る: LED の電流は `SGND` に流さない。J10 の GND は `GND-STAR` へ専用の線（U4 の GND と同じ扱い）。U6 は ESP32 のそばに置き、GND は `SGND`。
- 状態表示（電池の残り、止まった理由、選んでいる輪など）は**ファームだけで足す**。回路は変わらない。

## Constraints

- 入力:
  - 机上（I〜L）: 安定化電源 12.0V（XT60 のケーブルで J1 へ）。
  - 03 から: LiPo 3S 1500mAh 35C。公称 11.1V、満充電 12.6V、使い切り 9.0V（1セル 3.0V）。設計上の上限は 12.6V、下限は 9.0V
- ESP32 の電源:
  - 机上は USB（JP1 を外す）。
  - LiPo では U4 から（JP1 を挿す）。
- 組み方:
  - E-7（I〜K）までは、段階2のブレッドボードに輪1・輪2 を足す。
  - LiPo で床を走らせる前（L）に、ユニバーサル基板1枚へ移す。PCB は作らない。
- フットプリント: **割り当てない**（CLAUDE.md の決まり）。Layers / IPC class / Manufacturer min trace: 対象外
- 電流:
  - モータ1個あたり: 無負荷 0.13〜0.17A（段階1の E-2、段階2の G-2）、ストール 約 2.3A。
  - 3個同時のストールで 6.9A。U4 の入力（制御と LED）の 約 0.55A（9.0V のとき）を足して 約 7.5A。
    LED を足す前は制御の分 0.2A で 約 7.1A だった。U4 の入力の 0.55A は、LED 8個を全部白・最大にしたとき（U4 の出力 0.79A）の値。
  - 5V（U4、出力の絶対最大 1A）: ESP32 とエンコーダで 0.3A、U6 で 約 2mA、LED はふだん 0.4A まで（ファーム）で合計 0.7A（70%）。
    LED 8個を全部白・最大にしても 0.79A（79%）。
  - 机上は安定化電源の電流制限で頭打ち。ブレッドボードの間は 1.0A まで。
- Thermal: 室内、ケースなし、自然空冷。ドライバに放熱器は付けない。ストールを流し続けると許容損失を超えるので、LiPo ではファームのロック保護で守る（「保護」）
- EMI/EMC:
  - 規格の要求なし。
  - ブラシノイズは C3〜C5、ドライバのスイッチングは C7〜C9 と C1・C2 で抑える。
  - 接地は `PGND` と `SGND` を1点（`GND-STAR`）で合わせる（段階2と同じ）。

### 記号の変更

- 自作ライブラリ（`mobile-base.kicad_sym`）の段階2の4つ（`JGB37-520`、`BP5293-50`、`AE-TB67H450`、`ESP32-DevKitC-38`）は変えない。
- LED の口のために `SN74AHCT125N` を足した（2026-11-19）。
  - KiCad の `74xx:74AHCT125` は、4つのゲートと電源が別々の記号に分かれた形で、電源のピンが `power_in`。GND を `SGND` につなぐと、`SGND` には電源を出すピンが無いので ERC の誤りになる（PWR_FLAG は部品番号が図に出るので使わない）。
  - 自作の記号は 14 ピンを1つの箱にまとめ、実物を上から見たときと同じ並び（左 1〜7、右 14〜8）にした。ユニバーサル基板で配線するとき、図のピンの位置がそのまま実物の位置になる。
  - ピンの種類: OE・A は input、Y は tri_state、VCC・GND は passive（ほかの自作の記号と同じ決まり）。ピンの番号と名前は TI のデータシート（SCLS264R §4）のとおり。
- C15 は `Device:C_Polarized_Small`（極板の短い電解の記号）にした（配置の試し描きで、2026-11-19）。`C_Polarized` だと、3文字の部品番号「C15」が極板か「+」の印に 0.08mm かかる。
  C1・C2（2文字）は `C_Polarized` のまま。部品は同じ電解コンデンサで、記号の絵の大きさが違うだけ。
- エンコーダの差し込み口（J3・J6・J8）は、段階2の `Conn_01x04_Pin` ではなく `Screw_Terminal_01x04` で描く。完成形（ユニバーサル基板）の形に合わせるため。
  モータの J2 は段階2から `Screw_Terminal_01x02` で、それと揃う。
- SW1 は `Switch:SW_SPST`（2端子の ON-OFF）。

| L | ユニバーサル基板へ移す。J9・F2・C13・SW1 を入れる。① モータを外し、USB を抜いて JP1 を挿す ② JP1 を外し、USB とモータをつなぐ | ① 安定化電源だけ ② USB ＋ 安定化電源 | ① 0.2A ② 0.5A → 1.0A | ① TP1〜TP4・TP5・TP8・TP9、SW1 で全部が切れる ② K をやり直す |
| M | LiPo につなぐ（**03 の作業**） | LiPo | なし（F1・F2 と ファーム） | 03 の手順で。**その前にロック保護が働くことを机上で確かめる**（circuit.md §4） |

- **E-7 の電流制限は 1.5A ではなく 1.0A**（circuit-bringup.md は 1.5A）。ブレッドボードの接点の定格に合わせる（段階1・2と同じ理由）。
  3輪の無負荷 約 0.4〜0.5A は足りる。回り始めは一瞬 1.0A で頭打ちになる。ファームは強くするとき 1 秒かけて上げるので、3輪同時でも張り付き続けない。
  - ユニバーサル基板（L）もブレッドボードと同じ 1.0A のままにする。浮かせて回すだけなら足りる。
- **モータを回すのは ESP32 を USB で動かしているときだけ**（段階2と同じ）。電流制限に張り付くと VM が下がり、U4 が止まって ESP32 がリセットする。
  ESP32 を U4 から動かしたまま回すのは LiPo（M）から。LiPo なら 7A 流れても電池の内部抵抗と線で 1V 前後しか下がらない（U4 は 6.4V まで動く）。
- **SW1 を入れる前に ESP32 をリセットする**（circuit-bringup.md の決まり）。USB をつないでいるあいだは、SW1 を切っても ESP32 は止まらない。
  切る前に出していた指令のまま SW1 を入れ直すと、その瞬間に回り出す。
- USB と安定化電源を同時につなぐとき、**安定化電源の緑の GND 端子は使わない**（段階1で分かったこと）。
- **LED の口**は、組み終えた段階3の回路（stage3-procedure.md の段 0〜7 で合格）に足す。確かめる手順は回路図のあとで stage3-procedure.md に段 8 として書く。
  順は、U6 を挿さずに電源を入れて J10 の電圧を測る → U6 を挿して LED なしで測る → 電源を切って5個のテープをつなぐ、の予定。モータを回す確かめの間は LED を外すか消しておく（安定化電源の 1.0A の制限を LED で使わない）。

## 計算と根拠

- **U4 の負荷**: ESP32 の Bluetooth 送信のピーク 約130mA ＋ ボード 約20mA ＋ エンコーダ3個 約45mA ≒ 0.2A。circuit.md の見積もり 約0.3A を上限に使う（1A の 30%）。LED の口を足した後の合計は「LED の口」（0.7A、最悪 0.79A）。
- **F2（1A）**: U4 の入力電流は、電池がいちばん低い 9.0V で 5V × 0.3A ÷ 9.0V ÷ 効率 0.8 ≒ 0.21A（1A の 21%）。12.6V では 約 0.15A。
  LED の口を足した後は、ふだん（0.7A）で 0.49A（49%）、LED 8個を全部白・最大（0.79A）で 0.55A（55%）。2A のヒューズなら 28%。
  - データシートの条件は「3A 以下」。1A が無ければ 2A でよい（ふだん 25%、最悪 28%）。
  - 電源を入れた瞬間に U4 の内蔵のコンデンサを充電する電流は一瞬なので、F2 は切れない。
  - 平形 1A の抵抗（約 0.1〜0.3Ω）による電圧降下は 0.55A × 0.3Ω ≒ 0.17V で、U4 の入力の範囲（7V 以上）に影響しない。
- **F1（10A）**: 3輪同時のストールと制御・LED で 約 7.5A（75%。LED を足す前は 7.1A）。ストール 2.3A × 3 に耐え、配線の短絡で切れる。
  5A だと急加速で切れるおそれがある（hardware.md）。電池は 35C × 1.5Ah = 52.5A なので、7.5A（5.0C）は流せる。
- **U4 の入力コンデンサ（C13）**: 段階2は、C1 が U4 の VIN と同じ所にあったので外付けの入力コンデンサを省いた。
  段階3は F2（線付きのホルダ）が間に入り、C1 から見て VIN が線の先になる。そのうえ `VM` は3台のドライバの PWM で揺れる。
  データシート（ROHM BP5293 Rev.C、p.16〜17 の図28・29）は、ヒューズを直列に入れ、その後ろの VIN の端子の直近に Ci を置く形をすすめ、
  配線が長いときや入力電圧が大きく揺れるときは Ci が無いと「動作しない場合があります」と書いている。推奨値は 10µF のセラミック（p.2）。
  - 電源を入れたときに C13 を充電するエネルギーは ½ × 10µF × 12.6² ≒ 0.8mJ で、F2 は切れない。
    `VM` は C1・C2 の充電で 0.1ms ほどかけて上がるので、C13 と F2 の線とで電圧が跳ね上がる（共振する）ことも無い。
- **SW1（DC24V 10A 以上）**:
  - 電圧: 満充電 12.6V は 24V の 53%。「DC12V 20A」だけの表示のスイッチは、12.6V が表示を少し超えるので選ばない（bom-reviewer の指摘）。
  - 流れる電流: 最大 7.5A（10A の 75%、15A なら 50%）。
  - 切るとき: モータの巻線の電流が止まろうとして火花が出る。直流の定格があるので切れる。巻線に溜まっていたエネルギー（1個 約 5mJ と見積もる）は C1・C2 と D3 が受ける。
  - 入れるとき: C1・C2（2000µF）を充電する大きな電流が一瞬流れる。
    - 電池・ヒューズ・線・コンデンサの抵抗を合わせて 約 0.05〜0.1Ω と見ると、ピークは百数十 A、長さは 0.1〜0.2ms。
    - エネルギーは ½ × 2000µF × 12.6² ≒ 0.16J。XT60 を挿したときの小さな火花と同じもの。
    - F1 が溶けるのに要る I²t（平形 10A で数十 A²s）に対して 数 A²s なので、F1 は切れない。
  - **XT60 は SW1 を切った状態で挿す。** 突入の火花が XT60 ではなく SW1 の中で起きるようにするため。
- **SW1 を切ったあと**: U4 が `VM` 6.4V まで電気を使い、そこで止まる。残りは R1・R2（122kΩ）を通して抜けるので、2000µF × 122kΩ ≒ 4分かかる。
  - その間、TP1 には数 V 残る。基板を触る前に TP1 を測る。
  - 輪が惰性で回っていると、モータが発電して `VM` が少し残る。電池からの電気は来ないので加速はしない。
- **C1・C2 のリプル**: 3輪の PWM を同じ時刻に切り替える最悪の場合、床で走るとき（1輪 1A と見る）のリプル電流は 約 3 × 1A × √(0.5 × 0.5) = 1.5A。
  C1・C2 と電池で分ける。ZLH 1000µF/35V の許容（カタログで 2A 前後）以内。
- **分圧（R1・R2）**: 段階2と同じ。電池の電圧 [V] = 5.472 × `pinmV` / 1000 − 0.090（H-1。この ESP32 と R1・R2 の組み合わせのもの）。
  9.0V → 1.66V（式から）、12.6V → 2.32V（H-1 の実測）。ADC がまっすぐ読める 2.45V 以下。
- **R12〜R15**: R10・R11 と同じ。12.6V の線を間違えて挿したとき (12.6 − 3.6)V ÷ 4.7kΩ ≒ 1.9mA。内部プルアップ（約 45kΩ、少なく見て 30kΩ）と、
  エンコーダが L を出したときの電圧は 3.3V × 4.7 ÷ (4.7 + 30) ≒ 0.45V で、L と読める上限 0.83V より下（段階2の G で実際に数えられた）。
- **ESP32 のピン**: circuit.md §5 の割り当てどおり。PWM（LEDC）6本、エンコーダ（PCNT）3ユニットで、どちらも数が足りる。
  - IN1・IN2 につながるピン（GPIO19・21・22・23・25・26）は、起動の間は入力で、ドライバの内部プルダウン 100kΩ で L になる（モータは止まる）。
  - GPIO14 は起動の一瞬だけ出力になることがあるので、エンコーダの入力にして R12 で守る。
- **線の太さ**: 幹線と基板の母線は 14AWG（7.5A まで）。母線からドライバ1台への枝とモータの線は 2.3A まで。
  ユニバーサル基板の銅のランドはモータの電流を流すには細いので、電流は線（母線）に流し、ランドははんだ付けにだけ使う。
- **電圧の余裕**: C1・C2 36%、C3〜C13 25% 以下、SW1 53%、U1〜U3 29%（12.6V ÷ 44V）、U4 48%（12.6V ÷ 26V）、D3 の動作電圧 15.3V は 12.6V より上。
  LED の口: C14 10%、C15 31%（16V のとき）、U6 は 5.0V（推奨 4.5〜5.5V の中）。

### LED の口

元の資料: ROHM BP5293-xx データシート Rev.C（秋月の掲載、以下 BP）、TI SN74AHCT125 データシート SCLS264R（以下 AHCT）、SN74AHC125 SCLS256O、Worldsemi WS2812B データシート。

- **U4 の余裕**: 出力の絶対最大 1000mA（BP p.3「瞬時たりとも超えてはならない」。p.14 図26 で周囲温度が高いと下がる）。
  ふだんは ESP32 とエンコーダ 0.3A（上の「U4 の負荷」）＋ U6 約 2mA ＋ LED 0.4A（ファーム）で 0.70A（70%）。
  - **ハードの上限（LED 8個まで）**: ファームが誤って全部を白・最大にしても、0.3A ＋ 0.002A ＋ 8 × 0.061A ≒ 0.79A（79%）。9個では 0.85A、11個で 0.97A になり余裕が無い。
  - U4 の過電流の制限は、上側の MOSFET の電流（ほぼ出力の電流）が 1.9A で働く（BP p.6 の 2-3、p.17 の図30）。1〜1.9A のあいだは 5V も下がらず、U4 は定格を超えたまま動き続ける。
    データシートは、絶対最大定格を超えうるならヒューズなどの物理的な対策を求めている（p.20 の注意 1）。ここでは数を 8個に限って、超えうる状態を作らない。
  - U6 の電流: 静止 20µA 以下、入力が 3.4V 付近のとき1本につき 1.5mA 増える（AHCT §5.4 の ICC・ΔICC）。GPIO27 の H は 3.3V なのでこの増分がかかる。合わせて 約 2mA。
  - 熱: 5V × 0.7A を出すと U4 は数百 mW を熱にする。表面温度の上限は 105℃（BP p.13）。段 8 で LED を点けたまま数分置き、U4 が触れないほど熱くないことを確かめる。
- **WS2812B の電流**: 1個あたり、赤・緑・青を最大で 約 20mA ずつ、白で 約 60mA（よく使われる目安で、多めの値）。消えていても 約 1mA（版で 0.7〜1mA）。
  - 8個で: 全部を白・最大で 約 0.49A、1色・最大で 約 0.17A。ファームの上限 0.4A は、白に近い色を最大で点けたときだけ効く。
  - ファームの計算: 合計 [mA] = 個数 × 1 ＋ Σ（R + G + B）÷ 255 × 20。これが 400 を超えないように明るさを下げる。
  - 長いテープは 8個に切って使う（消えていても1個 約 1mA。切らずにつなぐと、全部が点いたときに U4 の 1A を超えうる）。
- **F2（1A）**: U4 が 0.7A を出すとき、電池がいちばん低い 9.0V で 5V × 0.7A ÷ 9.0V ÷ 効率 0.8 ≒ 0.49A（49%）。12.0V なら 0.36A。
- **安定化電源で確かめるとき**: LED 0.4A で 12.0V 側が 5V × 0.4A ÷ 12.0V ÷ 0.8 ≒ 0.21A 増える。モータの確かめ（1.0A の制限）と同時にはしない。
- **信号の電圧**:
  - WS2812B: DIN の H の下限 0.7 × VDD = 3.5V（VDD 5.0V）、L の上限 0.3 × VDD = 1.5V。ESP32 の H 3.3V は下限に届かない（新しい版には 0.55 × VDD のものもあるが、テープの LED の版は見て分からない）。
  - U6（AHCT）: 入力の H の下限 2.0V、L の上限 0.8V（AHCT §5.2、VCC 4.5〜5.5V）。ESP32 の 3.3V / 0V を余裕をもって読む。出力の H は 8mA 流して 3.8V 以上（VCC 4.5V のとき。AHCT §5.4）で、WS2812B の 3.5V を上回る。
  - SN74AHC125N（手元）: 入力の H の下限は VCC 3V で 2.1V、5.5V で 3.85V（SCLS256O §5.3。0.7 × VCC）。5.0V では 3.5V 前後で、ESP32 の 3.3V を H と読めない。
    §8.2.1 に「VCC 5.5V で VIH は 3.85V。HIGH = 3.3 V では低すぎる」とある。
  - 速さ: WS2812B の信号は 800kHz（いちばん短いパルス 0.4µs 前後）。U6 の遅れは 6.5ns 以下で、形はほぼ崩れない。
- **USB だけで動かしているとき**（12V なし。`+5V` が 0V で、U6 と LED に電源が無い）:
  - U6 の入力は VCC に向かうダイオードを持たず（入力の電圧の上限 7V が VCC に関係しない。入力の保護電流 IIK は VI < 0 の向きだけ。AHCT §5.1）、VCC が 0V でも入力の漏れは ±1µA 以下（§5.4 の II、VCC = 0〜5.5V）。
    GPIO27 が H になっても、ESP32 から U6・LED の側へ電流が流れ込まない。U6 を挟むもう一つの理由（ESP32 と LED を直接つながない）。
  - ファームも、`VBAT_SENSE` で 12V が来ていると分かるまで LED に信号を出さない。
- **C15（100µF）と U4 の起動**: U4 のソフトスタートは 2.5ms（typ.）。その間に出力のコンデンサを充電する電流と負荷の電流の合計が大きいと、過電流の制限（入力の電流 1.9A）がかかって立ち上がりが遅れ、
  出力が 3.5V 未満のまま 0.9ms 続くと短絡保護で 14.4ms 止まり、起動できないことがある（BP p.16〜17、図30-1〜30-3）。
  - 充電の電流 = C × 5V ÷ 2.5ms。100µF で 0.2A、220µF で 0.44A、470µF で 0.94A、1000µF で 2A。
  - 起動のときの負荷は ESP32・エンコーダ 0.3A ＋ 消えている LED（8個で 0.008A）。LED はファームが起動の後で点ける（BP p.20 の 5「起動時、出力は軽負荷の状態に」）。
  - 100µF なら合計 約 0.51A で 1.9A の 27%。220µF でも 0.75A（39%）。470µF は 1.25A（66%）で余裕が小さく、1000µF は超えるので付けない。
  - 電解にしたのは容量が要るため。U4 の出力に足すならセラミックと書かれている（BP p.17。リップルや急な負荷の変化のため）が、それは U4 の端子の直近に置くもの（入出力のコンデンサは内蔵。p.16）。
    C15 は LED の線の先で、LED が点滅するときの電流の山を受ける。
- **R16（330Ω）**: DIN の線の反射と、LED のテープの電源と信号の入る順のずれ（付け外しの途中など）で WS2812B の入力に流れる電流を抑える（Adafruit の目安 300〜500Ω）。
  DIN が GND と短絡すると 5V ÷ 330Ω ≒ 15mA。U6 の出力の絶対最大 ±25mA 以内（AHCT §5.1）。R16 の損失 76mW（1/8W の 61%）。
- **R17（10kΩ）**: ESP32 のリセット中は GPIO27 が入力で浮く。U6 の入力を浮かせると出力が揺れ、WS2812B がそれを信号と読んで勝手に光ることがある。10kΩ で L に保つ。
  GPIO27 が H のときに流れるのは 3.3V ÷ 10kΩ = 0.33mA。GPIO27 は起動の時に出力にならない（GPIO14 と違う）。
- **U6 の使わないゲート**: 入力（A・OE）を `SGND` に。TI の決まり（AHCT §5.2 の注 1「使わない入力は VCC か GND に保つ」）。出力は未接続でよい（AHCT §8.2.1.3「Unused outputs can be left floating」）。
  1OE は `SGND` で、1A の値がいつも 1Y に出る。
- **J10 の短絡**（LED を外しているときに `+5V` と GND の端子に何かが触れた、など）: U4 の過電流の制限と短絡保護（14.4ms 止まって再起動）で U4 は守られる（BP p.3・p.6）。
  ESP32 が U4 から動いていればリセットし、モータは止まる。データシートは「保護動作を続けて使わない」としているので、電源を切って直す。

## 保護

| 何から | どう守るか | 守らないもの・その理由 |
|---|---|---|
| 過電流・短絡（机上） | 安定化電源の電流制限（0.2A → 0.5A → 1.0A） | U1〜U3 の電流制限は使わない（circuit.md。RS を GND に直結） |
| 短絡（LiPo） | F1 10A（電池のすぐ後ろ） | — |
| U4 が壊れて VIN と VOUT が短絡し、大きな電流が流れ続ける | **F2 1A**（データシートが求める 3A 以下） | 机上は安定化電源の制限が代わり |
| 暴走・異常（ファームや無線が固まる） | **SW1**（非常停止を兼ねる）。電子部品を通らずに全部を切る | ファームの止める仕組み（デッドマン、指令ウォッチドッグ、ロック保護）がふだんの守り。SW1 はその後ろ |
| SW1 を入れ直したときに走り出す | LiPo では ESP32 ごと切れるので、起動後はスティックを中央に戻すまで出さない（ファーム） | USB をつないでいるときは ESP32 が止まらないので、入れる前に ESP32 をリセットする（「組む順番」） |
| モータのストールでの発熱（LiPo では電流制限が無い） | ファームのロック保護（g_teleop にある。M の前に机上で確かめる） | 2.3A を流し続けると 3.2W でドライバの許容 2.85W を超える。過熱保護（TSD）には頼らない（circuit.md §4） |
| 回生（逆転や急停止で `VM` が上がる） | D3 で 20V 前後に抑える。ファームは逆転の前に止めて待つ | LiPo につないでいれば電池が戻りの電流を吸うので、D3 が主に効くのは安定化電源の間と SW1 を切った直後 |
| 電池の使いすぎ（1セル 3.0V 未満で傷む） | ファームの低電圧保護（`VBAT_SENSE`。H-1 の式、移動平均で判定） | ファームは 03 で書く。SW1 を切ると分圧も切れるので、切っておけば電池から流れ続ける電流は無い。しまうときは XT60 も抜く |
| 逆接 | XT60 の形 | 逆接防止の部品は入れない（段階1と同じ理由）。D3 は逆接では順方向に流れる |
